# FreeCAD Codex Sidebar sponsorship plan, 26 October 2026

Status: planned, inactive. No funding channel has been activated under this
plan. The maintainer's payout jurisdiction and account eligibility remain
unverified.

Sponsorship would help cover maintenance time, reproducible CAD fixtures,
compatibility testing and the cost of model usage during development. Support
would be voluntary. Core source, installation instructions and normal use
would remain available without a sponsorship paywall. Contributions would
not buy a promised feature, delivery date, priority fix or support contract.

## Proposed rollout

1. **Prepare the public release.** Publish clear installation and rollback
   instructions, known limits and reproducible tests so potential supporters
   can assess the current project.
2. **Verify one funding route.** Confirm eligibility, total fees, payout
   requirements and the identity shown on receipts. Review payment privacy:
   for example, Ko-fi notes that a personal PayPal account typically exposes
   the creator's legal name and email. [Official privacy explanation](https://help.ko-fi.com/hc/en-us/articles/115004001294-What-personal-information-is-shared-on-Ko-fi-as-a-creator)
3. **Activate only after a separate maintainer decision.** Start with a
   voluntary contribution page and a clear description of permitted uses.
   Add a repository funding link only after the real account and URL are
   verified. No placeholder handles or payment credentials belong in source.
4. **Report actual use if funding starts.** Publish a monthly aggregate of
   gross support, fees, net receipts, spending by category and remaining
   balance. Separate maintenance time from paid testing costs. Publish
   completed work and measured results; keep future work as intentions.
   Obtain consent before naming supporters, and keep transaction details
   private.

## Supporting model usage and tests

“Token support” would mean funds earmarked for legitimate development usage,
or a separately agreed, opt-in test run with a stated spending cap. Each
participant would use their own authorized account. The project would not
solicit API keys, login credentials, subscription sharing or transferable
token balances. A contribution would not increase another user's account
limits or grant access to a shared Codex subscription.
Normal provider charges and usage limits would still apply.

Sponsored tests would use public or synthetic fixtures. Any contributor
would choose which sanitized results to share. Funding would not give
sponsors access to users' machines, CAD documents or conversations, and
would not change the sidebar's provider data flow. The participant would
still control what prompts and tool results they send through their chosen
provider. Company or confidential geometry would require its owner's
explicit authorization before sharing.
